# AI Watch

把多个 AI 助手的运行状态、等待提醒和剩余额度放在一个桌面面板里。支持 Claude、Codex、Antigravity、DeepSeek Harness、ZCode、Kimi、千问和 WorkBuddy；数据来自本机客户端及已接入的只读额度接口。

当前以 **macOS** 为验收平台，使用 Electron、React、TypeScript 和 Vite。Windows / Linux 提供构建入口，实际接入与窗口行为仍待对应平台验证。

### 窗口和日常操作

在 **配置 → 外观 → 窗口模式** 选择布局。单列宽度随屏幕可用高度变化，限制在 300–420 逻辑像素；双排宽度加倍，受屏幕可用宽度限制。卡片按内容决定高度，顶部工具栏和总览固定。

- **单列 / 双排**：上方卡片和下半屏各自滚动，所有开启的组件都可查看。双排下半屏固定两列，后续组件紧接所在列的上一块，不因旁边较高的组件留下整行空隙；展开模型或更多动态后会重新排布。看板娘排在最后时（默认顺序）固定在双排 / 全屏下半屏最底部并横跨所有列；把它排到其他位置后按普通组件参与分列，键盘 Alt + ↑ 可把底部的看板娘上移一格回到分列中。
- **全屏**：显示更宽的助手卡片与每个助手最多八条任务详情；只有客户端提供的名称、时间、操作摘要或进度才会显示。点击退出全屏或按 Escape 返回此前布局。全屏期间暂停跨桌面置顶。
- **收起**：缩为 64 逻辑像素宽的状态窄条，保留已启用助手的图标和状态。**收纳**则隐藏窗口与 Dock 图标，后台继续监看；点击菜单栏图标可看额度速览或恢复面板。
- **打开助手**：点击卡片 / 窄条头像或看板娘立绘。未识别到应用时，在 **配置 → 图片与应用 → 启动应用** 手动选择；头像也支持 Tab、Enter 和空格操作。
- **移动与排序**：拖动顶部移动整个窗口。卡片非按钮区域长按约半秒后拖动排序；下半屏从圆圈手柄直接拖动，靠近滚动区边缘会自动滚动。按 Escape 取消，也可聚焦卡片或手柄后用 Alt + 方向键调整。隐藏组件保留原顺序。
- **完全退出**：关闭窗口会收纳；通过菜单“退出 AI Watch”、配置“退出面板”或 `⌘Q` 停止后台监看。macOS 快捷键：`⌘⇧B` 展开 / 收起，`⌘⇧H` 收纳，`⌘⇧U` 额度速览。

**配置 → 关于** 只显示版本号、项目 GitHub 地址（点击用系统浏览器打开）和作者：Claude大小姐 · GPT龙娘。

外观、语言、模块和来源选择即时保存。首次启动按配置贴边；本次运行中可移动到其他屏幕，重启后回到默认停靠侧。菜单栏额度速览使用最近的后台快照，不会因打开菜单额外查询账号。

### 下半屏和看板娘

在 **配置 → 外观 → 下半屏** 开关各组件。关闭全部组件后，助手卡片列表使用完整可用区域。

| 组件 | 显示内容与展开方式 |
| --- | --- |
| 动态 | 已显示助手的开始、等待、完成、启动和退出记录，最新在上。默认最近 **50 条**，点击“展开更早动态”查看其余记录；本机最多保留近 24 小时的 300 条。 |
| 额度重置 | 按恢复 / 到期时间排序。Antigravity 默认只显示 **Gemini 4 Argon**，其他模型手动展开；Argon 没有有效未来重置时间时，回退到该助手最早恢复的一项。其他助手最多保留 7 项，没有 Antigravity 时为 8 项。 |
| 额度趋势 | 近 24 小时每个助手“最紧额度”的变化；需要积累至少两个采样点。 |
| 看板娘 | 仅二次元模式显示，优先提示等待处理、运行或额度紧张。点击右上角刷新按钮换一位已显示的助手说话；双排模式放大人物与气泡。 |

模型和动态展开后可以再次收起，重新打开应用默认收起。动态和趋势仅记录助手编号、状态、时间与百分比，不含任务内容；重启从新基线继续，不补造应用关闭期间的记录。双排的列高会随内容变化调整，下半屏使用统一滚动区域。

看板娘提供 **8 位助手各 150 条，共 1200 条中英台词**；中文界面用中文，其余语言用英文。多位助手时避免连续选同一位，近期台词尽量不重复；状态变化会切回提示。默认每 **15 秒** 自动换句，可关闭或设为 **5–300 秒**，底部进度条表示下一次刷新的时间。有助手工作时，每三句闲聊插播一次工作状态；手动换句重置倒计时，打开配置或拖动下半屏排序时暂停。

二次元图片会按用途裁成头像或半身像，普通 LOGO 与角色图独立保存。WorkBuddy 使用薄荷绿双马尾原创生成立绘，来源分类为 `generated-edit`，尺寸与提示词见[素材说明](docs/WORKBUDDY-ART.md)。自选图片支持 8 MB 内的 PNG、JPG、WebP，仅保存于本机；已有自选图优先于内置图片。

### 水冷小屏幕串流（Windows / macOS 15+）

这是 **原 AI Watch 的可选功能**，默认关闭，沿用原应用名称、配置目录和安装包。基于 XANALI 的展域传输代码，当前适配 `zhanyu` / PASE_1021；其他设备需新增适配器，不能仅更改设备名称使用。

在 **配置 → 小屏幕串流** 设置分辨率、帧率、码率、模块轮播间隔和看板娘，然后开启。默认 **2240 × 1080、30 FPS、8 Mbps**。连接前退出占用设备的 KANALI（包括 Screen.exe / UDB.exe）。启用后桌面显示串流参数和原有配置，仍可折叠为侧栏、最小化或收纳到托盘；关闭串流会恢复此前的桌面布局，并等待屏幕原厂界面恢复。

Mac 需要 **macOS 15 或更新版本**及匹配芯片的构建：M 系列使用 arm64，Intel 使用 x64。USB 直接连接 Mac；部分 Apple Silicon 笔记本会询问是否允许连接配件，请在解锁状态下允许。若接口被其他程序或系统驱动占用，设置页会提示错误；程序不会强制卸载驱动。串流只渲染 AI Watch 自己的页面，不需要屏幕录制权限。电脑系统睡眠期间不能保证持续串流。

- 当前 90° 曲面屏按展开画布 **左右 1:1** 分区，中间留出弯折间距。左侧每页四个 Agent（2×2），右上为原版看板娘及台词，右下为额度历史曲线。原生 2240×1080 的两侧分别接近正方形；半尺寸和方形画布也保持左右区域。复用三套皮肤、明暗主题和动效，超过四个 Agent、模型额度、积分和币种自动轮播。
- 左侧卡片按上下分区：上半放大头像并显示名字、套餐和状态，下半集中展示额度；圆环皮肤扩大头像与外环，保留呼吸光效。
- 额度历史显示近 24 小时各 Agent 的最低剩余百分比，每页最多四条曲线，跟随已有本机记录或 LAN 主客户端历史。单点只显示点，没有历史时显示“记录中”；不把余额、缺失值或历史不足补成零。关闭看板娘后曲线占满右侧。
- 小屏移除打开程序、排序、手动刷新、手动翻页等控件；串流期间主进程也拒绝打开程序、重排和手动刷新请求。原有参数、来源、图片、主题及同步配置仍可在桌面调整。
- 看板娘复用原版 **1200 条中英台词**、表情和状态播报，自动换句间隔沿用 **外观 → 下半屏**。小屏独立运行，桌面配置页打开、最小化或收纳都不会暂停台词；关闭自动刷新时仍显示状态台词。
- 当前提问或授权请求全屏显示：**左半角色、右半大号红字**，文字向右留出约一个大字的额外间距。多条提醒每 6 秒自动切换，角色和文字滑入淡入，底部显示轮换进度；有当前等待任务明细时，同一 Agent 的多条任务也分别展示。缺少明细时按 Agent 汇总，同时待回答和待授权分两行显示。普通状态刷新不重置轮换，关闭动效仍会换页；处理完成后恢复监看布局。过期任务、登录提示和辅助功能权限提示不会仅凭文字触发全屏提醒。仍需在电脑上的对应 Agent 中回答或授权。
- 局域网子客户端可将主客户端的状态显示到本机小屏；测试模式会同步到小屏并标为测试数据。系统减少动态效果和原有动效开关仍有效。

Windows 离屏渲染及无 USB 编码验证已通过；Mac Apple Silicon / Intel 均已通过原生构建、严格签名、离屏编码及打包应用启动检查。**实体展域设备的显示、帧率与退出恢复尚待实机验收**。构建、依赖准备、架构和验证范围见 [小屏幕串流说明](docs/SCREEN-STREAM.md)和[桥接组件资源](screen-bridge/README.md)。

发布流程从固定的 FFmpeg / x264 源码构建编码器，再构建并打包内部串流桥；Mac 额外包含固定源码构建的 libusb。Apple Silicon 与 Intel 分别原生构建，完整对应源码、构建脚本与许可证随包保留。CI 先完成不连接 USB 的真实编码检查，再检查安装包中的组件。缺少组件的自定义构建仍会禁用串流开关并说明原因。已发布的 **v0.20.0 Mac 包不含这次 Mac USB 移植**，需使用本分支的新构建。

### 测试模式

在 **配置 → 模块 → 测试模式** 选择合成的运行、待机、等待、低额度、历史值等场景，再查看测试面板。界面明确标为“测试模式”；不会启动 AI 任务、回答问题或批准授权。测试开关仅在当前界面会话有效，退出后恢复已收到的本地状态；桌面菜单栏继续显示后台实际数据。窗口与图片设置仍会正常保存。

### 多端同步（局域网）

在 **配置 → 多端同步** 选择本机角色，默认“独立”，不开任何端口。

- **主客户端**：在局域网内共享助手状态、额度、等待提醒、动态与趋势记录，显示 6 位配对码、本机局域网地址和端口（默认 47321，可改为 1024–65535）。首次开启时 macOS 可能询问是否允许 AI Watch 接受传入连接，请选择允许。
- **子客户端**：点击“搜索局域网主客户端”（UDP 47322 广播发现），或手动输入 `地址:端口`，再输入配对码即可连接。连接后停止读取本机助手，只显示主客户端的数据；顶部标签显示“同步 / 未同步”，断线后自动重连。外观、语言、布局和看板娘间隔仍按本机设置；打开应用、授权辅助功能等需在主客户端操作。
- **安全边界**：只接受局域网与本机回环地址，拒绝带浏览器来源的请求；配对码只用于一次换取随机长令牌，主客户端只保存令牌摘要，连续输错会被限流。同步内容会去掉凭据、密钥、本机路径等字段，不同步自选图片、启动应用路径和钩子配置。“重置配对码并断开所有设备”会让所有子客户端失效。连接为局域网明文 HTTP，请只在可信网络中使用。

## 数据来源与限制

先在本机正常安装并登录所需客户端，再打开面板。不同服务的额度、积分和金额保留各自单位，不相加为一个总量。套餐和额度分别判断：未知不等于 Free，额度用完不改变套餐，历史数值不代表当前可用。

| 模块 | 额度 / 套餐 | 活动与主要限制 |
| --- | --- | --- |
| Claude Desktop / Code | 匹配所选来源和账号的本地快照；可选使用已有登录联网查询 | Code 会话登记与可选状态钩子；登记文件中的“待授权 / 待回答”优先于辅助功能提示。普通桌面聊天依赖 macOS 辅助功能。两种来源隔离，不混用账号。 |
| Codex | 官方客户端账号额度接口，失败时使用明确标记的缓存或本地记录 | 本机桌面任务及等待通道，支持普通 / 异步提问、选项选择、命令 / 文件 / 权限授权。等待时优先显示红色“待回答 / 待授权”，处理后恢复；其他任务仍独立计数。API Key 登录没有订阅额度；独立 CLI、远程或未加载的任务可能不可见。 |
| Antigravity | 已运行客户端的本机语言服务接口 | 读取服务任务状态；接口属于客户端内部实现，升级可能影响兼容。未运行时不会用历史运行标记点亮状态灯。 |
| DeepSeek Harness | 已有账号登录态查询官方余额，分别显示 CNY / USD、现金与赠送金额 | 结合 v4 会话事件、存活进程和会话锁判断；格式、记录或进程证据不足时显示未知。 |
| ZCode | BigModel 个人 Coding Plan 的已有登录与套餐 Key | 本地回合遥测需要观察到新活动；等待状态暂不可区分。团队等其他套餐、自定义目录尚未接入。[说明](docs/ZCODE-INTEGRATION.md) |
| Kimi Code | 已有文件型 OAuth 登录对应的官方额度 | 经验证的本机服务可读取运行 / 等待；普通终端与旧 CLI 活动可能未知，真实账号额度和状态变化仍待专项验收。[说明](docs/KIMI-INTEGRATION.md) |
| Kimi Work | 正在运行的桌面客户端账号与会员共享积分 | 活动暂为未知；已验证 macOS 国内账号和默认目录。[说明](docs/KIMI-WORK-INTEGRATION.md) |
| 千问 | 桌面客户端已有登录与官方会员接口 | 需手动开启千问专属钥匙串读取；本地智能体活动可观察，普通聊天 / 云端 / 等待暂不可确认。真实积分响应仍有兼容限制。[说明](docs/QWEN-INTEGRATION.md) |
| WorkBuddy | 官方客户端本机 WBIPC 通道的套餐与资源摘要 | 已验证套餐和积分；活动依据当前账号记录的近期变化，首次采样、陈旧数据及等待授权保持未知。[说明](docs/WORKBUDDY-INTEGRATION.md) |

Codex 等待提醒直接读取当前桌面客户端的只读状态流，支持旧式 `turns` 和新的 canonical history。大型状态快照逐段解析，只缓存请求类别、问题数量及回答匹配所需的哈希；不缓存对话正文、问题选项、工具输入输出或授权命令。等待变化直接更新面板、菜单栏和小组件摘要，不等待额度查询完成。首份快照或修订丢失后会重订阅，旧消息不会重新点亮已处理的提醒。

该通道当前核对的是 macOS 客户端 v11 协议，只监看本机候选列表中的最多 32 个会话，已知等待优先保留。线上单帧最多 256 MiB，保留投影预算及每会话状态序列化上限各为 2 MiB，并限制节点 / 深度；超出资源界限或协议不兼容时等待通道可能不可用，不据此推断没有请求。Windows 尚未接入这个 Unix socket 等待通道，Linux 仍待实机验证。

Antigravity 主卡片将同一基础模型的 High / Medium / Low / Thinking 合并显示；值守台显示全部，表盘和角色栏显示前三项，悬停“另有 N 项”查看剩余内容。这与下半屏重置日程的 Argon 默认折叠分别生效。更多套餐边界见[套餐接入说明](docs/PLAN-INTEGRATION.md)。

**Claude 的可选入口**均在配置的数据来源中：

- **联网查询 Claude 额度**默认关闭，复用所选客户端的已有登录，只读查询官方套餐和额度；可能需要 macOS 钥匙串授权。不会自动登录、续期令牌或使用 API Key。依赖内部接口与当前登录格式，接口和服务政策变化可能影响使用，详见 [Claude 凭据使用说明](https://code.claude.com/docs/en/legal-and-compliance#authentication-and-credential-use)。
- **Claude Code 状态钩子**默认关闭，开启后向 Claude Code 用户设置登记面板脚本，关闭时只移除本面板拥有的条目。仅记录白名单事件元数据，不读取对话或工具参数，不输出授权决定。真实终端 / 桌面 Code 会话触发链路仍需客户端实测；Windows 暂不支持，Linux 未实机验收。
- **识别桌面活动（辅助功能）**用于普通桌面聊天的发送、停止、提问和授权控件，不读取聊天正文。需要为实际安装副本授权；授权成功不保证客户端所有窗口都能被读取。
- 会话登记会核对进程身份；启动时间明确不匹配时拒绝旧登记，避免 PID 复用误报。身份核对成功的长期 Code 会话不因文件十分钟未更新变成未知；缺少身份或查询失败仍按原有时效处理。真实连续十分钟任务观察尚未完成。

**隐私与可靠性**：OS 访问、登录读取及网络查询集中在 Electron 主进程，通过经过验证的窄 preload 接口向沙盒界面传递摘要。登录凭据不进入界面、日志或仓库；面板不发送任务、不批准授权、不替用户登录。仅在全屏按需读取有限任务标题和操作元数据，不向界面输出完整对话、命令参数或工具输出，退出全屏清除详情快照。自选图片、偏好与本地记录不上传。

数据有各自的采样、缓存与限流周期，刷新按钮不会绕过服务限制。客户端未运行、版本变化、权限不足、记录不完整或网络失败时，面板会显示离线、未知、历史或错误说明；额度读取成功并不能证明任务正在运行。已验证范围和历史未完成项分别记录于 [QA](docs/QA.md) 与 [Agent Log](Agent%20Log.md)。

维护者在 Actions 中对最新 `main` 手动运行 **Release installers**。`publish` 默认为 `false`，只构建、检查并保存 Actions 产物；需要公开发布时将 `publish` 设为 `true`。发布任务等待三个原生构建任务全部成功，在 GitHub 内部下载同一次运行的安装包、生成 `SHA256SUMS.txt`，并确认远端 `main` 仍指向本次运行的 `github.sha`。随后创建草稿 Release，将标签固定到该提交，上传并核对五个安装文件及校验清单，最后公开。若 `main` 已更新，须针对最新 `main` 重新构建。

仅验证 Mac 移植时可选 `macos_only: true`，Apple Silicon / Intel 两个原生任务会独立运行，不等待 Windows 交叉编译工具安装；该模式始终禁止发布。正式发布必须关闭此选项并完成三个平台的检查。

Release 正文来自 [v0.20.0 发布说明](docs/releases/v0.20.0.md)，来源提交和 CI 链接由工作流运行时附加。正式包仅额外包含一份明确标记的合成状态夹具，供 `npm run test:release -- <应用可执行文件>` 在独立临时配置中检查，不会读写真实账户。

## 本地开发与安装

需要 Node.js 22.16 或更新版本、npm；macOS 完整打包要求 macOS 15+、Xcode Command Line Tools、原生 Python 3.13、Go、pkg-config 和 nasm。串流构建会下载并验证固定上游源码，不需要外部 XANALI 文件夹；准备方法见[桥接说明](screen-bridge/README.md)。仅开发普通面板界面不需要串流构建依赖。

```sh
npm ci
npm run dev       # 界面服务与 Electron 窗口
npm run dev:web   # 仅浏览器预览，窗口和本机能力以桌面版为准
```

```sh
npm run build
npm start         # 启动已构建的桌面版
npm run pack:mac  # 生成当前 Mac 原生架构的 .app（含串流桥）
npm run dist:mac  # 生成当前架构的 DMG + ZIP；两种芯片分别构建
npm run dist:win  # 生成 Windows x64 NSIS 安装程序
```

打包输出位于 `release/`。普通 macOS 本地包使用 ad hoc 签名，尚未提供 Developer ID 签名和公证；更换签名后可能需要为最终安装副本重新授予辅助功能权限。升级前备份旧应用和完整用户数据，完全退出后替换原位置的应用，再启动；保留 `userData` 中的偏好和自选图片。不要覆盖正在运行的应用。

Electron 下载受限时，可复用依赖目录中与版本、架构匹配的发行版：

```sh
npm run build
npx --no-install electron-builder --mac --dir --config.electronDist=node_modules/electron/dist
```

`npm run dist:linux` 准备 AppImage 打包，仍需在对应系统验证。Windows 安装包的构建及启动检查与真实服务验收分别记录。构建、签名或启动成功不代替真实服务与系统能力验收。

面向 AI Agent 的结构化部署规格（目录结构、IPC、偏好字段、数据来源、构建与验证步骤）见 [AGENT-README.md](AGENT-README.md)。
