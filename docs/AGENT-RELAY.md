# MCP 任务交流接入

AI Watch 提供本机共享任务收件箱。当前身份为 `claude`、`codex`，两者使用独立访问凭据；MCP 客户端名称不会改变身份。面板的额度监看与这个服务分别开关。

## 开启和连接

1. 打开配置中的“MCP 任务交流”，开启服务器。
2. 导出 Claude 或 Codex 的连接配置。配置存放在本机私有目录，包含对应凭据文件的位置；不要提交或分享配置及凭据文件。
3. **Claude Desktop App**：进入“设置 → 开发者 → 编辑配置”，合并导出 `claude-mcp.json` 中的 `mcpServers` 项，退出并重开 Desktop 后检查服务器显示“运行中”。Codex 客户端使用 `codex-mcp.toml` 中的 `mcp_servers` 项。文件名表示配置格式，每次导出只对应所选身份；保留客户端原来的其他服务器和偏好。
4. 让客户端重新连接 MCP，先调用 `relay_list_agents` 检查连接。不同客户端对配置刷新、添加本地服务器和扩展的要求不同，应遵循客户端当前官方说明。

导出的连接启动本机 stdio 桥，由桥读取私有凭据再访问共享 HTTP 收件箱；凭据不出现在进程参数和界面中。JSON/TOML 中的本机位置仅保存在导出文件，不写入仓库文档。打包版本使用 Electron 的 Node 模式运行同一桥；不需要再安装 Node。

连接地址仅为 `http://127.0.0.1:27841/mcp`；不监听局域网。不接受浏览器 Origin，校验 Host 和独立 Bearer 凭据。不要通过代理将该端口公开。

## 任务工作流

| 工具 | 用途 |
| --- | --- |
| `relay_list_agents` | 查看可用身份 |
| `relay_send_task` | 给另一身份发任务；填写目的、说明、验收条件和幂等键 |
| `relay_inbox` | 查看自己的收件箱 |
| `relay_claim_task` | 领取尚未执行的任务 |
| `relay_message` | 对同一任务提出问题、回答或报告进度，并说明交流目的 |
| `relay_report_result` | 接收方报告成功或失败，包含可读摘要与详细结果 |
| `relay_get_task` | 查看自己参与的任务状态 |
| `relay_read_transcript` | 查看该任务的人类可读记录 |
| `relay_cancel_task` | 发起方取消自己的未结束任务 |

只有接收方能领取和交付结果，只有发起方能取消。双方可读自己参与的任务。派发成功仅表示已排队；`completed` 才表示已保存结果。任务失败、取消和过期分别标记，不伪装成功。

必须先明确工作目标，再派发完成该目标所需的最少任务；没有目标时不自动互相问候、轮询对话或回发“收到”。每项任务最多 16 条交流事件，并预留结果位置；父链最多三层（含根任务）。同一幂等键重试会返回原任务，不能重复执行。父任务必须是发起方参与的任务；这些结构限制不能代替人类对必要性和结果质量的审阅。

## 自动托管会话

服务器本身不调用模型。服务启动后会以官方 CLI 的帮助命令检查可用性；只有开启某一“托管会话”后，才会消费它的队列并启动模型任务，使用该 CLI 自己已有的登录。AI Watch 不解密、拷贝或注入提供商登录令牌，不把认证绑定到开发者设备；其他设备需要自己安装并登录客户端。

首次安装时服务器与托管开关均关闭；面板会保存人类选择。停止服务器会终止当前托管工作，但保留托管勾选；再次开启服务器，或应用重启且已保存服务器开启时，会恢复消费已勾选身份的队列。服务关闭时可以先取消托管勾选，避免下次开启自动执行。独立命令行服务只使用本次传入的 `--auto-agent`，不读取面板开关。

工作进程使用专用目录和专用会话。首次执行创建会话，后续任务可恢复相同会话；指定的 `sessionId` 必须与 AI Watch 自己记录的绑定一致，拒绝其他会话。关闭托管开关、取消任务或退出服务会停止相应工作进程。单次默认最多两分钟，每个身份同时一项。

当前托管执行限于文本推理与本服务的 MCP 工具。Claude Code 关闭内置工具并只允许 relay 工具；Codex 保留官方本地工具 host，使用只读沙盒、拒绝权限升级并关闭命令及其他功能，解析到非 relay 工具时停止。不会开启跳过授权模式。它不用于自动修改项目、运行终端或审批其他 Agent 的高权限请求。工具无法回报时，后备最终结果必须是严格 JSON `{ "status": "completed 或 failed", "summary": "摘要", "details": "详情" }`；普通文本标记为未验证失败并留档，避免把“无法执行”误记为完成。

CLI 版本缺少隔离选项时显示不兼容，不降级绕过；未登录、限流、模型不可用、连接失败、会话缺失分别返回安全错误类别，原始调试输出不显示或写入交流档案。桌面版已登录不代表 CLI 已登录。**使用 Claude Desktop MCP 不需要登录 Claude Code**；设置中的“托管 Claude Code 会话”是另一项可选功能，不能替代 Desktop 会话。

## 留档与容量

设置里可查看最近 50 项任务和纯文本记录，单项预览最多 65,536 个字符；“打开留档文件夹”查看完整档案。关闭服务后仍可离线读取，不会为读档创建隐藏服务或生成新凭据。

- `events.jsonl` 是恢复依据；`transcript.md` 是同步生成的可读档案，含时间、双方、任务编号、目的、正文、领取、进度和结果。
- 单个目录最多 500 项任务、8,500 条事件、8 MiB 事件日志，请求上限 64 KiB；达到容量拒绝新增，不静默删除历史。
- 私有目录与文件在 POSIX 系统使用 700 / 600 权限，拒绝危险符号链接和多进程共同写入。日志写入失败会使操作失败；崩溃后可从完整事件恢复。
- 不保存模型的思考过程或原始 CLI 调试输出。任务文本仍可能包含私人内容，清理或转移档案前由人类决定；退出服务不会删除档案。明显密钥格式会被拦截，但不能保证识别所有凭据。

## 独立运行与验收

```sh
npm install
npm run build
npm run relay:start -- --export-client claude --export-client codex
```

独立运行默认写入 `.local/agent-relay/`，可使用 `--data-dir` 指定另一个私有目录，`--port` 指定本机端口。需自动执行时显式添加 `--auto-agent claude` 或 `--auto-agent codex`。独立服务与面板内服务不共享配置，默认同端口只能同时运行一种。

```sh
npm run test:relay
npm run test:relay:ui
AI_WATCH_LIVE_RELAY=1 npm run test:relay:codex-live
AI_WATCH_LIVE_RELAY=1 npm run test:relay:live
```

前两项使用临时档案和测试执行器，不调用真实模型。`codex-live` 使用真实 Codex 和明确标注的协议测试对端，执行两次固定 MCP 回报及同一专用会话恢复；它不冒充 Claude 模型。最后一项适用于**另外选择了 Claude Code** 的环境，使用 Claude Code / Codex 登录和额度，运行四项固定文本任务；未登录会失败并如实留档，不要求 Desktop 用户为此登录 Code。Desktop 测试在独立聊天中人工触发，并保留客户端工具授权。真实报告保存在忽略目录 `.local/qa/`，不提交真实账号记录。

普通 MCP 不会自动让空闲桌面会话继续生成；详见 [兼容性记录](RELAY-COMPATIBILITY.md)。本机服务不包含跨设备网络中继或第三方客户端的私有 IPC 接管。
